# HU-02.02 · Ingresar datos en campos con validación visible

## 1. Descripción

| Parte | Contenido |
|---|---|
| **Plantilla** | Como **estudiante**, quiero **escribir en campos que me digan claramente qué falta o qué está mal**, para **completar formularios sin adivinar el formato**. |
| **Contexto** | Los formularios de login, materias, tareas, eventos y encargos usan los mismos campos. |
| **Reglas de negocio** | RN-1: la etiqueta está siempre visible arriba; el placeholder no la reemplaza. · RN-2: el mensaje de error **reemplaza** a la ayuda y se enlaza con `aria-describedby`. · RN-3: se valida al salir del campo (blur) y al enviar, nunca mientras se escribe la primera vez. · RN-4: el área de texto muestra el contador `n / máximo` y no deja pasar del máximo. · RN-5: el numérico con stepper respeta el mínimo, el máximo y el paso; los botones «−» y «+» se deshabilitan en los límites. |
| **Datos** | Props: `label`, `help`, `error`, `valid`, `disabled`, `type` (texto, búsqueda, contraseña, área de texto, número), `maxlength`, `min`, `max`, `step`. Integración con esquemas Zod. |
| **Supuestos** | |
| **Fuera de alcance** | Reglas concretas de cada formulario (en sus HU). |

## 2. Criterios de aceptación funcionales (CA-FE)

```gherkin
# language: es
Característica: Ingresar datos en campos con validación visible

  Escenario: CA-FE-01 Error reemplaza a la ayuda
    Dado el campo "Código SIS" con la ayuda "Texto de ayuda"
    Cuando escribo "2010" y salgo del campo
    Entonces el borde pasa a --warn
    Y en lugar de la ayuda veo "El código SIS debe tener 7 dígitos."

  Escenario: CA-FE-02 Campo válido
    Cuando escribo "2010016" en "Código SIS" y salgo del campo
    Entonces el borde pasa a --ok y aparece "✓"

  Escenario: CA-FE-03 Contador del área de texto
    Dado un área de texto con un máximo de 280 caracteres
    Cuando escribo 41 caracteres
    Entonces el contador muestra "41 / 280"
    Y al llegar a 280 no se aceptan más caracteres

  Esquema del escenario: CA-FE-04 Límites del stepper
    Dado el número con pasos con mínimo 1, máximo 40 y valor <valor>
    Entonces el botón <boton> está deshabilitado

    Ejemplos:
      | valor | boton |
      | 1     | −     |
      | 40    | +     |

  Escenario: CA-FE-05 Mostrar y ocultar contraseña
    Dado el campo "Contraseña" con texto escrito
    Cuando hago clic en "Mostrar"
    Entonces el texto se ve en claro y el botón dice "Ocultar"

  Escenario: CA-FE-06 Campo deshabilitado
    Entonces el campo deshabilitado "dpardo" tiene fondo --bg2 y no recibe foco
```

## 3. Criterios de aceptación no funcionales (CA-NF)

| ID | Atributo | Verificar | Condición | Resultado esperado |
|---|---|---|---|---|
| CA-NF-01 | Accesibilidad | Asociación de la etiqueta y el error | axe + lector de pantalla | Cada campo tiene `label for`; el error se anuncia al enfocar |
| CA-NF-02 | Accesibilidad | Contraste del placeholder y del borde | Ambos temas | Placeholder ≥ 4,5:1; borde ≥ 3:1 |
| CA-NF-03 | Usabilidad | Teclado móvil adecuado | `inputmode` | Numérico para SIS y páginas; `email` para correo |
