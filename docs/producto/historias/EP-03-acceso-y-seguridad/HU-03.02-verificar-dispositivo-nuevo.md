# HU-03.02 · Verificar un dispositivo nuevo con un código enviado a Gmail

## 1. Descripción

| Parte | Contenido |
|---|---|
| **Plantilla** | Como **titular de la cuenta**, quiero **confirmar con un código que llega a mi Gmail cada vez que entro desde un dispositivo nuevo**, para **que una contraseña robada no baste para entrar**. |
| **Contexto** | Supabase no trae un segundo factor por correo, así que se implementa aparte. Es el paso 2 de `Login`: «Revisa tu Gmail». |
| **Reglas de negocio** | RN-1: tras una contraseña válida, si la cookie firmada `dpardo_device` no está en `dispositivos_confiables`, se genera un código de **6 dígitos**. · RN-2: el código se guarda **como hash** en `codigos_verificacion`, vence a los **10 minutos** y admite **5 intentos**. · RN-3: se envía por correo desde el servidor (canal elegido en T-10). · RN-4: el middleware bloquea todo `(app)` hasta verificar; la sesión de Supabase existe pero queda marcada como `pendiente_2fa`. · RN-5: «Reenviar» se habilita tras una cuenta atrás de 60 s («Reenviar en 0:58») e invalida el código anterior. · RN-6: «‹ Volver» cierra la sesión pendiente y regresa al paso 1. · RN-7: el correo se muestra enmascarado: `jdiego•••@gmail.com`. |
| **Datos** | `codigos_verificacion(id, user_id, hash, proposito='login', vence_en, intentos, usado_en)`. Entrada: 6 campos de un dígito. |
| **Supuestos** | El correo llega en menos de 30 s (objetivo de T-10). |
| **Fuera de alcance** | Marcar el dispositivo como confiable (HU-03.03). |

## 2. Criterios de aceptación funcionales (CA-FE)

```gherkin
# language: es
Característica: Verificar un dispositivo nuevo

  Antecedentes:
    Dado que el navegador no tiene la cookie "dpardo_device" registrada
    Y que ingresé un usuario y una contraseña válidos

  Escenario: CA-FE-01 Pedir el código en un dispositivo nuevo
    Entonces veo "Revisa tu Gmail"
    Y el texto "Enviamos un código de 6 dígitos a jdiego•••@gmail.com porque es un dispositivo nuevo."
    Y llega un correo con un código de 6 dígitos

  Escenario: CA-FE-02 Verificar con el código correcto
    Cuando escribo los 6 dígitos correctos
    Y hago clic en "Verificar y entrar"
    Entonces entro a "/"

  Escenario: CA-FE-03 Pegar el código completo
    Cuando pego "482913" en el primer dígito
    Entonces los 6 campos se llenan y se envía la verificación sola

  Escenario: CA-FE-04 Código incorrecto
    Cuando escribo un código incorrecto
    Entonces los campos se sacuden y veo "Código incorrecto. Te quedan 4 intentos."

  Escenario: CA-FE-05 Agotar los intentos
    Dado que fallé 5 veces
    Entonces veo "Demasiados intentos. Vuelve a iniciar sesión."
    Y regreso al paso 1 sin sesión

  Escenario: CA-FE-06 Código vencido
    Dado que pasaron más de 10 minutos desde el envío
    Cuando escribo el código recibido
    Entonces veo "El código venció. Te enviamos uno nuevo." y llega otro correo

  Escenario: CA-FE-07 Reenviar tras la cuenta atrás
    Entonces "Reenviar en 0:58" está deshabilitado y cuenta hacia atrás
    Y al llegar a 0 se habilita "Reenviar"
    Y al usarlo, el código anterior deja de ser válido

  Escenario: CA-FE-08 No saltarse el paso 2
    Dado que estoy en el paso 2
    Cuando abro "/olimpo" en la barra de direcciones
    Entonces vuelvo a "Revisa tu Gmail"
```

## 3. Criterios de aceptación no funcionales (CA-NF)

| ID | Atributo | Verificar | Condición | Resultado esperado |
|---|---|---|---|---|
| CA-NF-01 | Seguridad | Almacenamiento del código | Consulta a `codigos_verificacion` | Solo el hash (HMAC-SHA-256 con secreto del servidor); nunca el código en claro, ni en logs |
| CA-NF-02 | Seguridad | Fuerza bruta | 5 intentos por código y 3 reenvíos por hora | El sexto intento y el cuarto reenvío se rechazan |
| CA-NF-03 | Seguridad | Cookie `dpardo_device` | Inspección | Firmada, `HttpOnly`, `Secure`, `SameSite=Lax`, sin datos personales |
| CA-NF-04 | Eficiencia | Entrega del correo | 10 envíos de prueba | p95 ≤ 30 s |
| CA-NF-05 | Accesibilidad | Campos del código | Lector de pantalla | Grupo «Código de verificación» con «Dígito 1» … «Dígito 6»; `autocomplete="one-time-code"` e `inputmode="numeric"` |
