# HU-16.04 · Cumplir los umbrales de accesibilidad y rendimiento en toda la plataforma

## 1. Descripción

| Parte | Contenido |
|---|---|
| **Plantilla** | Como **estudiante**, quiero **que toda la plataforma sea rápida y usable con teclado y lector de pantalla**, para **usarla cómodamente en cualquier dispositivo y situación**. |
| **Contexto** | Historia no funcional de cierre (hito H9). Audita las 17 rutas. |
| **Reglas de negocio** | RN-1: objetivo WCAG 2.2 AA. · RN-2: Lighthouse móvil ≥ 90 en Rendimiento, Accesibilidad, Buenas prácticas y PWA en las 17 rutas. · RN-3: axe sin violaciones *serious* ni *critical*. · RN-4: Core Web Vitals p75: LCP ≤ 2,5 s, INP ≤ 200 ms, CLS ≤ 0,1. · RN-5: las auditorías corren en CI y bloquean el merge si bajan del umbral. |

## 2. Criterios de aceptación funcionales (CA-FE)

Esta historia no tiene evento discreto; sus criterios son umbrales (sección 3). El único flujo verificable es el de CI:

```gherkin
# language: es

    Entonces el check "a11y" falla y el PR no se puede fusionar
```

## 3. Criterios de aceptación no funcionales (CA-NF)

| ID | Atributo | Verificar | Condición | Resultado esperado |
|---|---|---|---|---|
| CA-NF-01 | Usabilidad · accesibilidad | Violaciones de axe | 17 rutas × 2 temas × 3 anchos | 0 serious y 0 critical |
| CA-NF-02 | Usabilidad · accesibilidad | Uso con teclado | Recorrido de los flujos principales (login, encargar, aprobar, crear tarea) | Completables sin mouse, con foco visible |
| CA-NF-03 | Eficiencia | Lighthouse Rendimiento | Móvil, 4G simulada | ≥ 90 en las 17 rutas |
| CA-NF-04 | Eficiencia | Core Web Vitals | p75 de campo (Vercel Analytics) | LCP ≤ 2,5 s · INP ≤ 200 ms · CLS ≤ 0,1 |
| CA-NF-05 | Portabilidad | Lighthouse PWA | Build de producción | Instalable y con service worker válido |
| CA-NF-06 | Usabilidad · accesibilidad | Lector de pantalla | NVDA (Windows) y TalkBack (Android) | Los 4 flujos principales se completan |
