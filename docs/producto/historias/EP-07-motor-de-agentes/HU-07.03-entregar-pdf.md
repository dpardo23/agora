# HU-07.03 · Entregar el PDF en Storage y en Google Drive

## 1. Descripción

| Parte | Contenido |
|---|---|
| **Plantilla** | Como **dueño del Olimpo**, quiero **que cada PDF terminado se guarde en la plataforma y en la carpeta de Drive de la materia**, para **abrirlo desde la web o desde Drive en cualquier dispositivo**. |
| **Contexto** | Paso 9 «Entrega en Drive» (Clío · Drive API). |
| **Reglas de negocio** | RN-1: el PDF se sube al bucket privado `documentos/{user_id}/{trabajo_id}.pdf`. · RN-2: se copia a Drive en `Mi unidad / UMSS / {materia} / Olimpo` (o la raíz configurada en HU-04.04); si la carpeta no existe, se crea. · RN-3: se registra en `documentos` con `storage_path`, `drive_url`, `paginas` y `usd_lista`. · RN-4: si Drive falla, el trabajo se marca `entregado` con `drive_pendiente = true` y se reintenta cada 15 min hasta 24 h. · RN-5: el PDF solo se entrega si pasó la barrera de entrega (paso 8). |
| **Datos** | `documentos`, Storage, Drive API (alcance `drive.file`). |
| **Supuestos** | |
| **Fuera de alcance** | |

## 2. Criterios de aceptación funcionales (CA-FE)

```gherkin
# language: es
Característica: Entregar el PDF

  Escenario: CA-FE-01 Entrega completa
    Cuando el #17 de "Estadística II" supera la barrera de entrega
    Entonces el PDF queda en Storage y en "Mi unidad / UMSS / Estadística II / Olimpo"
    Y en "Documentos" el #17 muestra "Entregado" con "PDF"

  Escenario: CA-FE-02 Carpeta inexistente
    Dado que la carpeta de la materia no existe en Drive
    Cuando se entrega el PDF
    Entonces se crea la carpeta y el PDF queda dentro

  Escenario: CA-FE-03 Drive caído
    Dado que la API de Drive responde con error
    Cuando se entrega el PDF
    Entonces el #17 queda "Entregado" con el aviso "Copia en Drive pendiente"
    Y se reintenta hasta lograrlo
```
