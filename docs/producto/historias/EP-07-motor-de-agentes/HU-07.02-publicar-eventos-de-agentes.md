# HU-07.02 · Publicar el avance del pipeline como eventos de los agentes

## 1. Descripción

| Parte | Contenido |
|---|---|
| **Plantilla** | Como **dueño del Olimpo**, quiero **que el worker real emita los mismos eventos que el simulador**, para **que los dioses del Olimpo reflejen el trabajo verdadero**. |
| **Contexto** | La oficina y el registro (HU-05.02, HU-06.03) ya funcionan con el simulador (T-06). Aquí el emisor pasa a ser el worker. |
| **Reglas de negocio** | RN-1: por cada paso: `trabajo_pasos` pasa a `en_proceso` y luego a `hecho` o `error`, con `detalle`, `tokens_in`, `tokens_out`, `usd_lista` y `motor`. · RN-2: tipos de evento: `paso_iniciado`, `paso_terminado`, `traspaso`, `planificacion`, `paso_fallido` y `libre`. · RN-3: un `traspaso` se emite cuando el resultado de un paso pasa a otro dios (p. ej. Apolo → Temis con una sección). · RN-4: los mensajes son cortos (≤ 60 caracteres), en español y sin datos sensibles. · RN-5: el contrato de eventos se valida con un esquema compartido entre el simulador y el worker. |
| **Datos** | `eventos_agente`, `trabajo_pasos`. |
| **Supuestos** | |
| **Fuera de alcance** | |

## 2. Criterios de aceptación funcionales (CA-FE)

```gherkin
# language: es
Característica: Publicar eventos de los agentes

  Escenario: CA-FE-01 Inicio de un paso
    Cuando el worker inicia el paso 4 del #17
    Entonces se inserta "paso_iniciado" de "red" con el mensaje "Redacto sección 1 de 6"
    Y en la oficina Apolo va a su pupitre

  Escenario: CA-FE-02 Traspaso entre dioses
    Cuando Apolo termina la sección 1
    Entonces se inserta "traspaso" de "red" a "ver" con el mensaje "Llevo la sección 1"

  Escenario: CA-FE-03 Contrato compartido
    Dado el esquema de eventos del simulador
    Cuando el worker emite 100 eventos de un trabajo real
    Entonces el 100 % cumple el esquema

  Escenario: CA-FE-04 Fallo de un paso
    Cuando falla la compilación
    Entonces se inserta "paso_fallido" de "maq" con un resumen del error
    Y Hefesto va al Taller de Ares
```

## 3. Criterios de aceptación no funcionales (CA-NF)

| ID | Atributo | Verificar | Condición | Resultado esperado |
|---|---|---|---|---|

| CA-NF-02 | Seguridad | Contenido de los mensajes | Revisión de 1 trabajo | Sin claves, rutas internas ni correos |
